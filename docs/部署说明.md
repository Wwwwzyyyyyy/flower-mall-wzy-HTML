# 部署说明

## 一、本地快速启动

保持交付目录结构不变，运行 `start-local.cmd`。后端8080同时托管预构建前端，用户端及管理端使用相同域名的不同路径，接口仍采用HTTP前后端分离设计。

关闭启动窗口停止服务。首次启动自动创建持久化演示库与演示账号。若8080已被占用，请先停止本项目之前的实例，或设置 `PORT=8081` 后启动并改用对应端口。不要停止不属于本项目的服务。

## 二、MySQL 8.0模式

1. 在MySQL中执行 `database/create-database.sql`，将占位密码改成你自己的数据库密码。账号和库均可按需调整。
2. 配置环境变量（PowerShell示例）：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'mysql'
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/flower_mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
$env:DB_USER = 'flower'
$env:DB_PASSWORD = '数据库密码'
$env:JWT_SECRET = '请替换为至少32位独立随机字符串'
$env:ADMIN_PASSWORD = '请替换为首次管理员登录密码'
$env:UPLOAD_DIR = 'D:/flower-upload'
# 如需演示账号、商品，首次运行前设置true；正常业务保持false
$env:SEED_DEMO = 'false'
cd backend
java -jar target/flower-mall-1.0.0.jar
```

3. 应用启动时执行资源目录的 `schema.sql` 建表；数据库目录中的同名文件是供手工导入的副本。管理员 `admin` 的密码仅首次创建时取 `ADMIN_PASSWORD`，后续改环境变量不会重置既有密码。
4. 首次自动初始化6个分类及10种花语。`SEED_DEMO=true` 仅用于全新演示库，自动建立演示商品和用户；已存在分类的库不会再次灌入演示商品。不要在已有业务库上反复导入演示SQL。
5. 首次建表后执行一次 `database/indexes.sql`。脚本再次运行会报索引重名，可通过数据库索引列表确认是否已执行。
6. 另有 `database/init-base.sql`（基础分类/花语）和 `database/init-demo.sql`（演示商品及图片），面向**空白库手工初始化**。应用自动初始化与手工初始化二选一，避免重复数据。

默认使用MySQL的InnoDB引擎与utf8mb4字符集；数据库服务须启用事务。交付测试使用MySQL 8.0.44真实实例验证核心流程。

## 三、国内服务器部署

- 使用国内可访问的云服务器或局域网服务器，安装Java17、MySQL8、Nginx。无需在服务器运行npm，只需上传预构建dist和JAR。
- 将项目放入 `/opt/flower-mall`，上传目录设为 `/var/lib/flower-mall/uploads`，赋予运行账号读写权限。
- 使用 `deploy/env.example` 建立 `/etc/flower-mall.env`，替换数据库密码、JWT密钥、管理员初始密码和AI配置；限制文件仅运行账号/管理员可读。
- 按 `deploy/flower-mall.service` 建立系统服务；运行目录必须为backend。设置服务器时区为Asia/Shanghai或启动JVM时添加 `-Duser.timezone=Asia/Shanghai`，确保经营日/月口径一致。
- 修改 `deploy/nginx.conf` 的域名、证书及目录。公网入口使用HTTPS，8080只供Nginx访问。生产可加 `--server.address=127.0.0.1` 绑定后端。
- 前端不加载Google Fonts、海外CDN、远程商品图等；用户浏览和本地模板祝福无需连接AI服务。真实AI请求仅由后端向你配置的服务发起。
- 国内公网域名部署的备案等事宜需按部署平台和当地要求办理。本交付不包含服务器、域名、证书和服务商账号。

## 四、构建和升级

前端Node.js建议20.19+或22，后端JDK17+、Maven3.9+。

```powershell
cd frontend
npm.cmd ci --no-audit --no-fund
npm.cmd run build
cd ../backend
mvn.cmd -s settings-cn.xml clean package
```

中国镜像配置可按自己的网络修改。首轮已通过国内镜像构建，交付ZIP带dist和JAR，因此普通体验不需要下载依赖。

升级前备份数据库及图片，再停止旧实例、替换JAR/dist并启动。本版schema仅创建不存在的表，**不是自动数据库迁移工具**；后续表结构调整需提供独立版本迁移脚本。

## 五、备份

MySQL使用 `mysqldump --single-transaction --default-character-set=utf8mb4` 导出业务库；密码使用受保护的客户端配置或交互输入，勿写到共享脚本。同步备份 `UPLOAD_DIR` 全目录，保留与数据库同一时间点的引用关系。

本地H2演示库在停止应用后备份 `backend/data/`。正式MySQL环境不使用此目录保存订单。恢复时同时恢复数据库和图片文件。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 8080端口占用 | 停止本项目旧实例，或设置PORT换端口 |
| H2提示文件被占用 | 同一data目录只启动一个应用实例 |
| MySQL无法连接 | 检查服务、数据库名、账号权限、DB_URL与密码 |
| JWT_SECRET报错 | mysql配置必须设置至少32字符的独立密钥 |
| 管理员密码与环境变量不一致 | ADMIN_PASSWORD仅初始化时生效，已有库保留原密码哈希 |
| 访问8080只有404 | 确认工作目录为backend，且../frontend/dist/index.html存在 |
| AI提示连接/额度异常 | 核对兼容服务根地址、模型、密钥、余额及网络，Key不能放到前端 |
| 图片上传失败 | 检查实际格式、5MB限制、3000万像素限制与上传目录写权限 |
| 退款处于处理中 | 等待最多约5秒，点击刷新；失败后按失败原因处理并重试 |
